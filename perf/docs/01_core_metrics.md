# 性能测试核心指标

> Day 1 学习笔记 · 6 大核心指标 + 定义 + 关系

---

## 一、6 大核心指标

| 指标 | 英文 | 定义 | 说明 |
|------|------|------|------|
| 响应时间 | Response Time (RT) | 请求从发出到收到响应的时间 | 最直观的性能指标，用户感知最强 |
| 吞吐量 | Throughput | 单位时间内处理的请求数 | 衡量系统处理能力的上限 |
| TPS | Transactions Per Second | 每秒事务数 | 吞吐量的一种，按事务统计 |
| 并发数 | Concurrent Users (VU) | 同时在线的虚拟用户数 | 不等于 TPS，需结合思考时间 |
| 错误率 | Error Rate | 失败请求占总请求的比例 | 性能测试必须关注的质量指标 |
| 资源利用率 | Resource Utilization | CPU/内存/磁盘/网络使用率 | 判断瓶颈在哪里的关键 |

---

## 二、指标之间的关系

### VU ≠ TPS（新手最容易混淆）

**核心公式**：
```
TPS = VU / (平均响应时间 + 思考时间)
```

**举例**：
- 100 个 VU，每个请求响应时间 500ms，思考时间（sleep）1s
- 每个用户 1 个请求耗时 = 0.5s + 1s = 1.5s
- 每个用户每秒发出请求 = 1/1.5 ≈ 0.67 个
- TPS = 100 × 0.67 ≈ 67

**去掉思考时间**：
- 100 个 VU，响应时间 500ms，无 sleep
- 每个用户每秒发出请求 = 1/0.5 = 2 个
- TPS = 100 × 2 = 200

**结论**：VU 数一样，TPS 可能差 3 倍。VU 只是并发用户数，TPS 才是真正的系统吞吐能力。

### TPS vs QPS

| 概念 | 含义 | 关系 |
|------|------|------|
| TPS | 每秒事务数 | 一个事务可能包含多个请求 |
| QPS | 每秒查询数 | 单个接口的请求频率 |

举例：一个"下单"事务包含 4 个请求（浏览 → 选商品 → 下单 → 支付），那 1 TPS ≈ 4 QPS。

### 响应时间与资源利用率

| CPU 使用率 | 响应时间表现 | 说明 |
|------------|-------------|------|
| < 50% | 稳定低延迟 | 系统轻松 |
| 50-70% | 略有波动 | 正常负载 |
| 70-90% | 开始上升 | 接近瓶颈 |
| > 90% | 急剧上升 | 瓶颈已现 |
| 100% | 队列堆积 | 严重瓶颈 |

---

## 三、指标分层

### 用户层（用户感知）
- 响应时间（RT）：用户等多久
- 错误率：用户看到多少报错

### 系统层（吞吐能力）
- TPS：系统每秒处理多少事务
- 吞吐量：系统每秒处理多少数据
- 并发数：系统同时服务多少用户

### 资源层（硬件瓶颈）
- CPU 使用率
- 内存使用量
- 磁盘 I/O
- 网络带宽

---

## 四、典型指标基线参考

| 指标 | 优秀 | 良好 | 可接受 | 需优化 |
|------|------|------|--------|--------|
| RT (avg) | < 100ms | 100-500ms | 500ms-1s | > 1s |
| TPS | > 1000 | 500-1000 | 100-500 | < 100 |
| 错误率 | 0% | < 0.1% | < 1% | > 1% |
| CPU | < 50% | 50-70% | 70-90% | > 90% |
| 内存 | < 60% | 60-75% | 75-85% | > 85% |
