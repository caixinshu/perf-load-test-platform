## 五、项目三预习：AI 应用质量评测平台

### AI 应用测试 vs 传统应用测试的区别

| 维度 | 传统应用测试 | AI 应用测试 |
|------|------------|------------|
| 输出 | 确定性（给定输入，输出固定） | 不确定性（相同输入可能不同输出） |
| 评判标准 | 对错明确 | 主观性强，依赖语境和意图 |
| 交互方式 | 单轮请求-响应 | 多轮对话、上下文依赖 |
| 测试用例 | 输入-预期输出 | 输入-评分维度（流畅性/相关性/准确性） |

### LLM 评测的核心难点

1. **输出不确定性**：同一 prompt 多次调用结果不同，需要多次采样统计
2. **多轮对话**：上下文累积，后续回答依赖前文，测试用例需模拟完整对话
3. **主观性**：答案好坏没有绝对标准，需要多维评分

### 主流评测方法

- **人工评测**：质量最高但成本高、不可扩展
- **自动评测**：基于规则/N-gram 匹配（BLEU、ROUGE、BLEURT）
- **大模型打分**：用 GPT-4 等强模型作为裁判（LLM-as-a-Judge）

### 常见评测指标

| 指标 | 适用场景 | 原理 |
|------|---------|------|
| BLEU | 翻译/生成文本 | N-gram 重叠度 |
| ROUGE | 摘要 | N-gram 召回率 |
| BLEURT | 生成质量 | 基于 BERT 的学习型指标 |
| GPT-4 评分 | 通用 | LLM-as-a-Judge，多维打分 |

### 思考：AI 应用质量评测平台设计

如果要做一个 AI 应用质量评测平台，核心模块设计：

1. **测试用例管理**：支持单轮/多轮对话场景，包含 prompt、上下文、期望维度
2. **评测引擎**：批量调用被测 LLM，支持多次采样
3. **评分模块**：集成多种评分方式（自动指标 + LLM-as-a-Judge + 人工审核）
4. **对比分析**：不同模型/版本/参数的横向对比
5. **报告生成**：多维度评测报告 + 趋势分析
6. **回归评测**：版本迭代时自动回归，监控质量退化
